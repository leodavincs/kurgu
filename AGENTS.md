# AGENTS.md: Kurgu

Kurgu is a local Premiere-style timeline editor for videos that an agent writes as code. You (the agent) write and edit `project.json`; the human fine-tunes it in a browser editor; `render.py` turns it into an mp4. Everything runs on `127.0.0.1`. Contract: `SPEC.md`. **Field reference for writing projects: `skills/kurgu/reference.md` (read it before writing a project from scratch).**

## Setup

Install with one line: `curl -LsSf https://raw.githubusercontent.com/leodavincs/kurgu/main/install.sh | sh` (macOS / Linux) or `powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/leodavincs/kurgu/main/install.ps1 | iex"` (Windows): Python 3.10+ and ffmpeg are fetched when missing; commands `kurgu`, `kurgu-render`, `kurgu-mcp`, `kurgu-notes`. `kurgu doctor` says what is missing or wrong. In a clone: a virtualenv with `pip install -r requirements.txt` (`python scripts/check_deps.py`). Tests: `python -m pytest -q`. Use `python` (or `py -3` on Windows) where this file says `python3`.

## Workflow

1. Put every asset in `<dir>/media/` (fonts in `<dir>/fonts/`); reference it relatively (`"src": "media/clip.mp4"`). Probe durations with `ffprobe` so `start`/`end`/`duration` match reality.
2. Write `<dir>/project.json`. Layers array: first element is front-most. Every layer gets a short stable `id` and a readable `name`.
3. Start the editor and tell the human the URL: `open_editor` (MCP) or `python3 server.py <dir> --no-open` in the background.
4. Look before you show: render stills (`render_frame`, or `python3 render.py <dir> --frame 12.3 --output /tmp/f.png --draft`) at the first frame, each title, and the end. Fix what is off.
5. **Brief.** `<dir>/brief.md` is the video's creative brief (max 250 words, short bullets: what it is, audience/platform, tone/style, hard rules, open decisions). Read it before editing (`get_brief`). Whenever the human states intent, style, audience or a rule about the video, update it (`update_brief`: full replace, max 2000 chars; without MCP edit the file). No secrets/paths/personal data. Ask AI in the editor passes it to its agent.
6. **Before every follow-up edit, re-read what the human did:** current `project.json`, the tail of `changes.md` (one line per manual edit; respect them, do not revert values they set), and `.kurgu/state.json` (`{time, selected, playing, language, updated}`: "this text" = the selected layer(s), "here" = `time`). If `project.json` has `notes`, they are the human's timeline comments (Notes panel). When the human says "apply my notes" / "notlarımı uygula": `get_notes` (open ones, with the layers under each), handle each at its time, then `update_note` it with `done: true` and a one-line `reply` ("Blur reduced 22→8"; shown under the note). Resolve, do not delete; `add_note` to flag something.
   **Watch + note loop:** the human can watch the video in the editor (*İzle + not*, or Review mode) and click Send. The exact agent loop is **wait → fix → done → wait**: `kurgu notes wait <dir>` (MCP `notes_wait`) returns the notes of every send you have not consumed yet and otherwise blocks until he sends (omitted `--timeout` = forever; `--timeout 0` = look once, exit 3 when nothing is new; MCP default 120 s, 0 = look once). A saved cursor (`.kurgu/inbox.cursor`, each inbox entry has a `seq`) records what you already got, so a send made while you were fixing is returned by the next wait, never lost; notes that were already marked done are not handed out again, and a note stamped `sent` whose inbox line was never written (a crash) is delivered once as `recovered`. `--since N` peeks at sends above seq N without touching the cursor. Notes get `sent` (timestamp); `NOTLAR.md` in the project folder lists each with timecode, layers at that time, a frame JPEG under `.kurgu/notes/` and, when he drew on the frame, the marks (burned into the JPEG, plus `hint` and layers under each mark). Fix each, then `kurgu notes done <dir> <id...> --reply "what you changed"` (MCP `notes_done`), then `kurgu notes wait <dir>` again. `kurgu notes list <dir> [--open|--sent|--all] [--json]` shows what is still to fix (default `--sent`). `kurgu notes …` runs `agent_notes.py` directly (also installed as `kurgu-notes`); a project folder named `notes` is opened as `kurgu ./notes`.

   **Placing or moving something for a note.** Each note lists the layers then on screen with `bounds` (`left/top/right/bottom/w/h`, project px, the rendered box) and an `anchor` line saying what the layer's x/y mean. For a text layer x/y is the block CENTRE even with `align=left` (align only aligns lines inside the block), so the left edge is `x - w/2`. Compute x/y from the anchor and bounds so an edge lines up with nearby content: another layer's bounds, or something visible in the note frame (text burned into a video clip is not a layer, so read its position off the picture; `kurgu detect` gives approximate boxes). Keep the box inside the frame.

   **Look before you close.** After the edit run `kurgu frame <dir> <seconds> -o /tmp/look.jpg` (MCP `render_frame`) at the note's time, view the image, adjust, and only then `notes_done`. The default frame is the half-size draft (`--full` for project size), so image px x2 = project px.

   **Vague notes (interpret or ask).** If the note gives a direction or target, apply the best change in that direction and state the values and any remaining compromise in the reply. Ask only when no reading satisfies the note's core request, or the change would be destructive. A vague note with no direction gets the smallest clear reading, stated with its values. To ask, leave the note open with `kurgu notes ask <dir> <id> --question "..."` (MCP `notes_ask`). After `notes ask` the note is `asked`: the editor shows your question with an answer box, and the answer returns as a new send (`question` + `answer` on the note). Every `--reply` states the concrete values you chose and how to change them ("start moved to 4.6 s; lower `start` for earlier") plus every compromise or unchecked part: the human reads the reply, not your output. Never copy a template or plugin file in as a stand-in for a requested asset (a subscribe animation, a logo): if it is missing, ask. Text burned into the footage cannot be edited: say what is possible (cut, speed, an overlay of a frozen frame) and that such overlays are fragile when the layer under them has keys.

   **Burned-in text and shapes.** Pixels Kurgu did not draw (text or shapes in footage, 3D or other tools' renders) have no layer `bounds` and no element map. `kurgu detect <dir> <seconds> [--layer ID]` (alias `kurgu ocr`; MCP `detect`) finds text lines and shapes with boxes in PROJECT px. They are approximate (`approx: true`): still look at the frame before aligning anything to them.

   **Code-made clips (`source`).** A layer in a note's `layers` that has `source` (`kind`, `unit`, `file`, `frame`, `time_in_unit`, `render`) was produced by code. Fix the SOURCE file (and line, when given), at the source `frame` shown, instead of adding overlay layers or patching keys on the timeline. For alignment use `elements_under` on a mark (`under mark:` in NOTLAR.md): project-px boxes plus `file:line`, measured from the clip's element map, not estimated. After a change in the source, run `kurgu rerender <dir> <unit>` (MCP `rerender`; the unit is `source.unit`, or give the layer id): it regenerates only that unit with the adaptor named in `source.render`; the editor reloads it. Which frames belong to the unit comes from the scene list (`source.list`, e.g. `shots.json`, read fresh each time; `source.unit_start_frame` + `source.frames` when there is no list): change a scene's length THERE, then rerender. When several scenes share one film file the unit gets its own file (`film.<unit>.mp4`) and its layer is pointed at it; the film and the other scenes are never rewritten. The unit's layers get the new end when the length changed, and the output names the later scene layers you must shift (by how many seconds); `project.json` is otherwise not touched. Audio is the matching slice of the old file. Then LOOK (`kurgu frame` / `kurgu strip`) before `notes done`. Chrome cannot start inside Codex's macOS sandbox: there `kurgu rerender` says so. The video is then UNCHANGED, so do NOT mark the note done: fix the source, then ask (`kurgu notes ask <dir> <id> --question "Source fixed; please run: kurgu rerender <project> <unit>"`), or leave it sent and say so in your reply. For a cinecode film (`source.kind` cinecode) the sound mix also lives in `<film folder>/audio/mix.json` (`gain_db` per bus): when you change volume or envelope in project.json, change it there too, or a re-import brings the old mix back (`kurgu help audio`). If the Kurgu in front of you has no `rerender`, say in your reply that a re-render is needed. Layers without `source`: all the rules above stay as they are. The element map comes from `kurgu elements <page> --frames ...` and `kurgu import <folder> [--elements]` builds a project from a scene list (see SPEC.md section 11).

   **Checking over time.** For a fade, a move or timing against other layers make ONE call, `kurgu strip <dir> <t0> <t1> --n 6` (MCP `render_strip`): a single labelled contact sheet, so view one JPEG instead of making many `kurgu frame` calls (frame is for one moment or full detail). Each layer in a note's `layers` has `start`, `end` and, if animated, `keys`; read them first to know when to look, then confirm with one strip over [start, end]. Tile px x the printed scale = project px.

   **Audio facts.** (Layer volume, `envelope` for ducking and the cinecode `audio/mix.json`: `kurgu help audio`.) Each note's `audio` block (inbox JSON; a `- audio:` line in NOTLAR.md) is already measured around the note time per sound layer, in project seconds: `peak_db`/`rms_db` (volume and envelope included), `silences`, and `words` when a transcript exists. Use it instead of running ffprobe/ffmpeg yourself; a layer with `error` was not analysed. Bounds flagged `approx` / "(estimate)" are a fallback: check them on the frame before moving or aligning anything.

   **One command per call.** When woken headlessly, run one command per call (no `;` / `&&` chains) and use only: `kurgu notes wait|list|done|ask|add <dir> ...`, `kurgu frame <dir> <sec>`, `kurgu strip <dir> <t0> <t1>`, `kurgu rerender <dir> <unit>`, `kurgu detect <dir> <sec>`, `kurgu probe <dir> [layer]` (media facts: use it, not ffprobe), and read-only discovery: `kurgu --help`, `kurgu <command> --help`, `kurgu help <topic>` (topics: `audio` = volume, envelope for ducking, cinecode mix.json); no python, ffmpeg, ffprobe or render.py. If something does not work, `kurgu report <dir>` prints one plain-text report to paste into an issue (nothing is sent anywhere).

   **"Kurgu notlarımı bekle" / "Wait for my Kurgu notes".** The editor's *Send* box offers a copyable phrase (Turkish: "Kurgu notlarımı bekle ve gelince uygula"). When the user says it, enter the loop and stay in it: `notes_wait` (or `kurgu notes wait <dir>`, see below for how to wait on your agent) → fix → `notes_done` → `notes_wait` again, until the user tells you to stop. The editor shows that an agent is listening (a heartbeat in `.kurgu/listening.json` while `notes wait` blocks). "Apply my Kurgu notes" without "wait" means one pass over what is already sent.

   **Which session gets woken.** Kurgu records the agent session that runs its commands (or the MCP server) in this project in `.kurgu/agents.json`, from the environment only, never from project files. The wake hook (`kurgu setup-agent --claude|--codex --wake`) then resumes exactly that session, not just "the last one in the folder"; a session older than a day, or one with no recorded id, falls back to a new headless run. You do nothing for this beyond running `kurgu` commands from the session the user talks to.

   **Which agent are you? (waiting for the user's notes).** The loop is always: check for sends, fix each note, `notes_done`, check again. Only the waiting differs. At the **start of every turn**, look once whether notes arrived: `notes_wait` with `timeout: 0`, or `kurgu notes wait <dir> --timeout 0` (exit 3 = nothing new).

   - **Claude Code:** run `kurgu notes wait <dir>` (no timeout) as a background command; you are re-invoked when it exits.
   - **Codex (CLI / IDE / desktop) and other agents:** a background process does not wake you, and long shell calls may be yielded or cut (~30 s observed). Wait with the MCP `notes_wait` tool (`timeout: 120`, or 3000 when the user says they are watching live; register it with `kurgu setup-agent --codex`, which raises Codex's 60 s tool timeout to 3600 s) and call it again when it times out. Without MCP: `kurgu notes wait <dir> --timeout 20`, repeated on exit 3. Or let Kurgu start you: `kurgu setup-agent --codex --wake` makes every Send run `codex exec resume` in the project folder (see AGENTS.md). If you cannot loop, say "send your notes, then tell me 'check notes'" and stop.
   - Codex needs write access to the project folder and to run `ffmpeg`/`kurgu-render`: use sandbox `workspace-write` (start Codex inside the project folder or add it with `--add-dir`), and allow the editor's localhost server (`127.0.0.1`) if your approval policy asks.
   <!-- kurgu:generated:end -->
   **Wake the agent when he presses Send (optional):** `kurgu setup-agent --codex --wake` (or `--claude --wake`; `--dry-run` shows it, `--no-wake` removes it) sets `on_send` in the USER config (`~/.config/kurgu/config.json`, `%APPDATA%\kurgu\config.json`; env `KURGU_CONFIG` = the folder that holds `config.json`, or the config file itself; env `KURGU_ON_SEND` = JSON argv list): Kurgu then runs it detached in the project folder after every send (placeholders `{dir}` `{seq}` `{count}` `{file}`; env `KURGU_PROJECT_DIR`, `KURGU_SEQ`, `KURGU_NOTES_COUNT`, `KURGU_NOTES_FILE`; output in `.kurgu/hook.log`; one run at a time, sends meanwhile make one follow-up run). It is never read from a project's `.kurgu/config.json`. The hook is `kurgu wake <codex|claude> {dir} {seq}`. It resumes the session Kurgu recorded for this project (`.kurgu/agents.json`, written from the environment of the agent that runs `kurgu` commands or the MCP server; older than a day or none recorded: no resume). Claude Code: `claude --bg --resume <session id> "<prompt>" --permission-mode acceptEdits --allowedTools "Bash(kurgu notes:*),Bash(kurgu frame:*),Bash(kurgu strip:*),Bash(kurgu rerender:*),Bash(kurgu detect:*),mcp__kurgu"` (continues that session in the background; Claude starts a copy itself when it is busy), then `claude -p "<prompt>" --continue --output-format json ...` (the folder's last session), then a fresh `claude -p`; when the last session was active in the last 2 minutes it starts a separate one instead of continuing it. Codex: `codex exec resume <session id> --json -c sandbox_mode="workspace-write" -c approval_policy="never" "<prompt>"` (`resume --last` when no session is recorded), or a new `codex exec -s workspace-write ... --skip-git-repo-check -C {dir} --json` when that session was active in the last 2 minutes or the resume fails; Codex runs in its own `CODEX_HOME` with Kurgu's command rules (`codex_policy`). Source folders outside the project that you trust (`kurgu import` records them in your user config for that project) are made writable: Claude gets `--add-dir <folder>`, Codex gets `-c sandbox_workspace_write.writable_roots=[...]`. Token usage / cost end up in `.kurgu/hook.log` (every line the agent printed starts with `| `); the editor shows the run's status from `.kurgu/wake.json`. Trade-off: the headless run is not live; Kurgu shows the result as "düzeltildi" + the agent's reply.
7. Render a draft first (`--draft`, half resolution), full quality only when the human says it is right.

## Rules

- Keep ids stable; never regenerate ids of existing layers. Patch `project.json`, do not overwrite it wholesale once the human has been editing.
- Do not touch `.kurgu/` except reading `state.json`.
- Times are seconds on the timeline; `end` is exclusive; `duration` must cover the last layer's `end`.
- Text `font` is a font id (e.g. `inter-bold`), not a file name. Turkish text needs ş ğ ı İ ö ü ç: all bundled fonts have them.
- No personal or private data in `project.json`.

## MCP tools (preferred when your agent has them)

Same powers over MCP (`mcp_server.py`, stdio, zero dependencies). Every tool takes an optional `project_dir` (default: server cwd or `$KURGU_PROJECT_DIR`).

| tool | what it does |
|---|---|
| `open_editor` | start the browser editor if needed, return the URL |
| `get_state` | selection + playhead, with full JSON of the selected layers (says if the editor is closed / state stale) |
| `get_project` | normalised project; `summary: true` = compact layer table |
| `edit_project` | atomic batch: `update:[{id,set}]`, `add:[layer]` (+`index`), `remove:[ids]`, `project:{...}`, `summary`. Validated; invalid batches are rejected whole. Goes through the running editor (live reload, backup, changes.md `[agent]` line) or writes the file directly |
| `render_frame` | one PNG frame (image), `t`, `draft` |
| `render` | full render, `draft` (progress notifications) |
| `get_notes`, `update_note`, `add_note` | read open/done notes with the layers at their time; resolve/edit/reply; leave an agent note |
| `notes_list`, `notes_wait`, `notes_done`, `notes_ask` | notes the human sent from watch mode: list (default sent), block until he sends, mark fixed with a reply (state the values chosen), or ask him a question (`asked`) when no reading meets the note's core request or the change is destructive |
| `get_brief`, `update_brief` | read / fully replace `brief.md` (max 2000 chars; logs `[agent] brief updated`) |
| `get_changes` | tail of `changes.md` (what the human did by hand) |
| `transcribe`, `make_captions` | optional local speech-to-text (needs `pip install mlx-whisper` or `faster-whisper`): word timings in timeline time; one `text` layer per caption chunk in group "Captions" (`cap_1`, ...) |
| `list_fonts`, `list_media`, `import_file` | font ids, media with durations, copy a file into `media/`/`fonts/` |

With MCP: `get_state` + `get_changes` before each edit, change the project only via `edit_project`, check with `render_frame`. Without it, do the same by editing the files and running `render.py`.

Setup snippets for Claude Code, Codex CLI, Cursor and Gemini CLI: `README.md`, section "Use with other agents".

## Code map

`schema.py` (defaults, normalisation, validation), `fonts.py` (registry), `anim.py` + `web/js/anim.js` (motion maths twins: keyframes, easing, seeded wiggle; shared vectors in `tests/anim_vectors.json`), `presets.py` (cam.punch / ken-burns / shake baked into keys), `server.py` (local HTTP API), `render.py` (numpy + ffmpeg), `transcribe.py` + `captions.py` (optional local Whisper, caption chunking), `mcp_server.py` (MCP over stdio, reuses the others), `ai.py` ("Ask AI": `POST /api/ai` runs the user's own `claude`/`codex` CLI headless with the Kurgu MCP tools; override with `KURGU_AGENT_CMD` or `agent_cmd` in the user-level `~/.config/kurgu/config.json` (never from the project's `.kurgu/config.json`: a project folder is untrusted; that file only takes `agent`, `ai_timeout`, `brief_timeout`); the Codex fallback is experimental; UI in `web/js/ai.js`; the box is a conversation thread: sessions resumed via `--resume`, threads in `.kurgu/ai-threads.json`, run from `.kurgu/ai-work/` so they never mix with the user's own terminal sessions; `brief.md` + `POST /api/brief/generate` summarise the terminal conversation with `claude -p --continue --fork-session`), `web/` (editor; `web/js/platform.js` = Mac/Windows modifier + `{mod}`/`{shift}`/`{alt}`/`{modkey}` placeholders in i18n strings, never hard-code ⌘; `web/js/merge.js` = pure three-way merge after a 409 save conflict, node-tested by `tests/test_merge.py`). Code and JSON keys are English; UI text goes through `web/i18n/{en,tr}.json`.
